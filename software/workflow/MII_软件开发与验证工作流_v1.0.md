# MII 软件开发与验证工作流 v1.0

## 1. 目的和适用范围

本工作流用于在现有 MII V7 实物板上开发并验证：硬件驱动、低功耗静态展示、BME280、本地模板、GNSS轨迹、Android App、BLE和局域网同步。

开始任何阶段前先阅读上级 `software/README.md`。屏幕示例、规格书、当前 V7 引脚和已知不兼容项均由上级入口统一索引，工作流不把示例配置视为产品配置。

## 2. 工作流原则

1. 先实物驱动，后业务功能。
2. 先单模块，后双模块，最后整机。
3. 每次只增加一个主要变量。
4. 所有硬件访问经过 `board_v7` 和驱动层。
5. 所有等待都有超时；所有传输可重试；所有持久化可恢复。
6. 编译通过不等于实物通过，实物通过不等于长时间稳定。
7. 没有测量记录的性能、功耗和容量不得写成已验证。
8. 阶段门槛未通过，不进入依赖它的下一阶段。
9. 轻量优先且先调研复用：新模块、依赖或架构修改先核对 GitHub/厂商/固定
   ESP-IDF 实现，记录许可证、兼容性、依赖与资源代价，再最小实施。
   具体记录见 `../docs/reuse-decisions.md`。
10. 每个检查点记录实际启用配置、Flash/静态 RAM 增量与任务/缓冲预算；
    链接裁剪和主机测试不替代完整功能及实板堆/栈/功耗测量。

## 3. 每阶段统一记录

每个阶段建立一份版本化测试报告，至少包含：

```text
硬件版本和板号
固件提交/版本
Android版本（如适用）
ESP-IDF和构建环境
测试日期
供电方式和电池状态
操作步骤
预期结果
实际结果
串口/USB日志
最小空闲堆
最大连续空闲块
任务栈最低余量
固件和分区占用
耗时
电流（适用时）
失败现象和复现方法
结论：通过/条件通过/失败
```

报告建议存入：

```text
software/verification\<阶段>\<日期-版本>.md
```

## W0：实物板身份和资料冻结

### 输入

- MII V7 实物板。
- `详细接线逻辑_v0.3.md`。
- `MII_V7_六层PCB详细接线与布局说明_v1.0.md`。
- EPD0426A02 原厂资料和项目示例。

### 执行

1. 记录实物板版本、ESP模组丝印、屏幕型号、GNSS和BME280模块标识。
2. 对照实物与设计文件确认关键电源、引脚和有效电平。
3. 确认主控为 `ESP32-S3-MINI-1-N8`，8 MB Flash、无 PSRAM。
4. 确认屏幕为 `EPD0426A02`、SSD1677、800 × 480、4线SPI。
5. 确认GPIO0按键/BOOT复用、GPIO21 PSHOLD和GPIO15 GNSS_EN。
6. 拍摄或记录板号、模组丝印和FPC方向，避免测试板混淆。

### 输出

- `board_v7`基线表。
- 实物板身份记录。
- 已确认差异清单。

### 退出门槛

- 实物、原理定义和软件引脚表无未解释冲突。
- 若存在冲突，先更新硬件基线并审批，不允许在驱动中临时写死补丁。

## W1：工程、工具链和协议骨架

### 执行

建立建议目录：

```text
software/firmware\
software/android\
software/protocol\
software/tools\
software/verification\
```

固件采用 ESP-IDF + C++，Android 采用 Kotlin + Jetpack Compose，设备消息采用 Protobuf/nanopb。

设置：

- `sdkconfig.defaults.v7_n8`，明确关闭 PSRAM。
- V7分区表草案。
- 固件、协议、存储、模板和App的独立版本号。
- Debug 与 Release 构建配置。
- 主机单元测试和静态检查入口。
- 协议代码生成和固定测试向量。

### 输出

- 可构建的空固件和空Android工程。
- 可生成的协议代码。
- 构建环境记录。

### 退出门槛

- 固件在N8目标配置下构建并烧录。
- Android Debug APK构建成功。
- C/C++与Kotlin对同一协议测试向量编码结果一致。

## W2：板级支持、电源和按键

### 开发顺序

1. `board_v7`引脚、极性和能力表。
2. 启动时立即设置GPIO21 PSHOLD。
3. GNSS_EN默认关闭、LED默认熄灭、EPD CS保持安全状态。
4. 复位原因、唤醒原因和启动日志。
5. STM6601 PBOUT、/INT和正常关机时序。
6. CHG_SENSE、PGOOD和BAT_ADC。
7. 三键消抖、短按、长按和组合键。
8. GPIO0启动保护。

### 必测场景

- 正常开机、短按、电源长按关机。
- 长按硬复位。
- 开机时按住/释放GPIO0功能键。
- USB供电、电池供电、充电中和拔线。
- 写入前、写入中和写入后触发关机。
- 连续100次开关机。

### 退出门槛

- 无意外掉电、BOOT模式误入或数据提交死锁。
- BAT_ADC与外部测量完成校准记录。
- 关机顺序可重复，GPIO21只在最后释放。

## W3：EPD0426A02 驱动 bring-up

### 强制前置查询

先从上级 `software/README.md`进入以下资料：

- EPD0426A02规格书。
- SSD1677规格书。
- 转接板原理参考。
- 4灰波表。
- `epd_ssd1677.c/.h`、`epd_init.c/.h`和`epd_text.c/.h`示例。

不得复用示例 `board_pins.h`；不得复用启用PSRAM的示例 `sdkconfig`。

### 开发顺序

1. 使用 `board_v7` 的GPIO7～12建立SPI和控制脚。
2. 验证硬复位和BUSY实际极性。
3. 所有BUSY等待增加超时和错误返回。
4. 白屏、黑屏和棋盘测试。
5. 验证物理方向、逻辑800×480/480×800转换和边界坐标。
6. 显示示例黑白图。
7. 显示示例4灰阶图。
8. 验证黑白局部刷新、残影和连续局刷后的完整刷新。
9. 验证屏幕休眠、设备深睡和重新初始化。
10. 将整屏 `malloc` 改为Flash流式读取和8～16 KB固定缓冲。
11. 加入屏幕断开、BUSY卡住和SPI失败恢复。

### 退出门槛

- N8无PSRAM配置下通过黑白、4灰阶和局刷。
- 驱动没有无限等待、未受控动态分配和示例GPIO依赖。
- 连续刷新不重启、不泄漏，方向和像素边界正确。
- 记录完整刷新、局刷耗时、内存水位和实测电流。

## W4：BME280 驱动与环境记录

### 开发顺序

1. 初始化GPIO5/6 I2C。
2. 检测0x76和芯片ID。
3. 读取校准参数并验证补偿计算。
4. 使用强制测量模式。
5. 生成温度、湿度、气压和质量标志。
6. 实现省电、平衡、高频三种采样档位。
7. 将采样事件交给存储服务。
8. 实现I2C超时、总线恢复和设备离线状态。

### 退出门槛

- 实物连续采样、深睡唤醒采样和断线恢复通过。
- 页面能显示最后更新时间和无效占位值。
- 不包含阈值判断、报警和后台通知逻辑。

## W5：GNSS驱动与运动状态机

### 开发顺序

1. GPIO15控制 `3V3_GNSS`。
2. GPIO17/18 UART接收，确认实物波特率和语句类型。
3. NMEA流式解析与校验和。
4. GPIO16 1PPS中断时间戳。
5. 搜星、有效定位、信号丢失和恢复状态。
6. 手动开始、暂停、继续、结束和二次确认。
7. `TrackSession → TrackSegment → TrackPoint`。
8. 步行、骑行和其他采样策略。
9. 暂停和结束时的电源策略。
10. 未正常结束轨迹的重启恢复。

### 退出门槛

- 冷启动、室外定位、信号丢失、恢复和关机流程有实测记录。
- 无效定位不进入正常轨迹。
- UART和1PPS长时间运行无溢出、阻塞或任务栈异常。
- GNSS关闭后确认电源状态符合设计。

## W6：设备持久化与容量回收

### 开发顺序

1. 根据实际固件大小冻结8 MB分区表。
2. 建立NVS、OTA A/B、模板、临时区和环形记录区。
3. 实现带CRC和提交标记的追加记录块。
4. GNSS点以32～64点批量写入。
5. BME280按批次写入。
6. 建立记录序号、同步游标和可回收标志。
7. 保存当前模板和上一模板。
8. 实现模板原子切换。
9. 实现软容量和硬容量回收。

### 必测场景

- 每个写入阶段强制断电。
- 记录区写满并循环覆盖。
- CRC错误和不完整块。
- 模板下载中断。
- 当前模板损坏后回滚。
- 未同步数据接近硬容量。

### 退出门槛

- 任意断电后可启动且已提交记录不丢失。
- 未确认同步的数据不会在软阈值清理。
- 实际分区容量覆盖目标活动页面和最低离线轨迹时长。

## W7：设备服务和页面状态机

### 开发内容

- 顶层运行状态和状态转换。
- 页面列表、当前页和手动刷新。
- BME280动态槽位。
- 无操作进入展示待机。
- 定时唤醒和再次休眠。
- 真正关机保留最后画面。
- GNSS页面、搜星页面和运动摘要。
- 设备错误降级页面。

### 退出门槛

- 业务层无裸GPIO、SPI、I2C或UART访问。
- 状态转换可由主机测试覆盖。
- 静态待机、定时采样、交互、GNSS和关机无冲突。

## W8：BLE绑定、控制和增量同步

### 开发顺序

1. Companion设备发现和首次连接。
2. MII显示配对验证码并要求按键确认。
3. 生成并保存设备独立密钥和令牌。
4. 状态、设置和页面控制协议。
5. 目录、版本和同步游标比较。
6. Protobuf消息分帧。
7. 小数据上传下载。
8. 大数据分块、校验、确认和断点续传。
9. 重连和错误恢复。

### 退出门槛

- 首次绑定、正常重连、解除绑定和恢复出厂通过。
- 不同MTU和连接中断下可恢复。
- 重复消息、重复块和乱序响应不会产生重复数据或错误状态。

## W9：Android本地数据与基础页面

### 开发内容

- Room数据库和迁移。
- App私有资源目录。
- Device、Template、Sensor、Track、Firmware、Backup Repository。
- 设备、设计、数据、设置四个一级页面。
- BLE连接状态和明确同步进度。
- 环境历史、CSV导出。
- 运动列表、地图和GPX导出。
- 完整备份和恢复。

### 退出门槛

- App进程被系统终止后，本地草稿和已同步数据仍在。
- 数据库迁移、重复同步和大轨迹分页通过。
- 地图使用显示抽稀，导出仍使用完整点。

## W10：Android模板编辑器与编译器

### 开发顺序

1. 固定800×480设备画布和方向模型。
2. 文字、图片、图形、温度、湿度、气压、电量、时间槽位。
3. 拖动、缩放、图层、锁定、复制、删除、撤销和重做。
4. 对齐线、网格、安全边界和重叠提示。
5. 模拟传感器值和墨水屏预览。
6. 静态文字、图片和复杂排版栅格化。
7. 黑白/4灰阶转换、缩放和抖动。
8. 生成背景、动态槽位、清单、版本和哈希。
9. 在Android参考渲染和设备实显之间做像素对比。

### 退出门槛

- 编辑过程流畅，不在拖动时反复编译整页。
- 边界、坐标、旋转和字体结果确定。
- 相同模板重复编译得到一致输出。
- 实物显示与App预览的方向、槽位和主要像素一致。

## W11：局域网和手机热点高速同步

### 开发顺序

1. App同步期间启动本地HTTPS服务。
2. 首次绑定时向MII保存手机证书指纹和设备令牌。
3. BLE下发本次手机IP、端口和同步计划。
4. MII连接已保存的家庭Wi-Fi。
5. 无共同局域网时由App创建临时热点。
6. 模板、资源、BME280、轨迹和固件分块传输。
7. 文件直接落盘，禁止整文件进入RAM。
8. 中断恢复、重复块、超时和资源回收。
9. 同步结束后关闭本地服务和设备Wi-Fi。

### 固定同步顺序

```text
认证与目录
→ 上传BME280
→ 上传GNSS轨迹
→ Android事务确认
→ 下发配置
→ 下发模板
→ MII应用并回报
→ OTA（如有）
→ 保存检查点并断开
```

### 退出门槛

- 家庭局域网、手机热点和BLE后备三条路径均有结果记录。
- 模板与轨迹中断后能从确认偏移继续。
- BLE切换Wi-Fi重复运行无内存泄漏。
- GNSS运动中不会自动启动Wi-Fi批量同步。

## W12：OTA、恢复和诊断

### 开发内容

- App本地导入固件包。
- 硬件版本、固件版本、大小和哈希检查。
- OTA写入非活动分区。
- 首次启动自检和确认。
- 启动失败回滚。
- 用户可读错误码、导出诊断和恢复页面。

### 退出门槛

- 正常升级、重复升级、错误硬件包、损坏包、传输中断和首次启动失败均有结果。
- OTA失败不破坏设备侧轨迹、传感器和模板数据。

## W13：整机性能和稳定性

### 关键场景

1. 展示待机与5分钟BME280采样。
2. 连续页面切换和局部刷新。
3. 4灰阶完整页面。
4. GNSS长时间记录并切换摘要页。
5. BLE连接、分块和断点续传。
6. BLE协商后切到局域网Wi-Fi。
7. 大模板和大轨迹同时排队同步。
8. 同步中断、App退出、手机锁屏和设备掉电。
9. 记录区满、模板区满和低电量。
10. 24小时、72小时及更长稳定性。

### 必须记录

- 各状态最小空闲堆和最大连续块。
- 每个任务栈最低余量。
- 显示、GNSS、BLE、Wi-Fi和存储耗时。
- 关机、待机、采样、搜星、记录、刷新和同步电流。
- 固件、OTA和数据分区余量。
- 墨水屏残影、完整刷新恢复和方向一致性。

### 停止条件

出现以下任一情况时停止增加功能并返回对应驱动阶段：

- 内存分配失败、看门狗或不可解释重启。
- 最大连续空闲块低于下一操作所需缓冲且无稳定余量。
- 存储断电后无法恢复。
- BUSY、UART、I2C或网络等待无超时退出。
- 同步确认前数据被删除。
- 当前模板和上一模板同时不可恢复。
- 功耗或温升超过硬件允许范围。

### 退出门槛

- 所有第一版使用流程都有实物端到端记录。
- 性能和容量预算以测量值更新到整体设计说明。
- 没有未解释的重启、数据丢失、死锁或无限等待。

## 4. 端到端功能验收

第一版完成必须同时通过以下流程：

### 静态展示

```text
App自由设计模板
→ 编译预览
→ BLE协商
→ 局域网/热点下发
→ MII校验并切换
→ 展示待机
→ 定时采集BME280
→ 局部更新动态槽位
→ 手机再次连接并取回历史
```

### GNSS运动

```text
按键开始
→ GNSS上电搜星
→ 有效定位后记录
→ 页面查看摘要
→ 暂停/继续
→ 结束并提交
→ 手机连接
→ 增量同步
→ Android地图绘制
→ GPX导出
```

### 故障恢复

```text
模板传输中断/写入断电/同步断开/OTA失败
→ 重启
→ 扫描已提交记录
→ 保留旧页面和未确认数据
→ 从同步检查点继续
→ App显示明确结果
```

## 5. 第一版完成定义

只有以下条件全部满足，才能宣布第一版完成：

- V7实物板全部基础驱动通过。
- 静态展示、BME280、GNSS、BLE和Wi-Fi端到端通过。
- Android自由模板与实物显示一致。
- 未同步数据在断电、断连和重试中不丢失、不重复。
- N8无PSRAM场景下无内存失败。
- 实测容量、性能和功耗已记录。
- OTA、回滚、备份和恢复通过。
- 所有发布物版本一致且可追溯。
