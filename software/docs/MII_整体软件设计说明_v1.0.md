# MII 整体软件设计说明 v1.0

## 1. 文档目的

本文定义 MII V7 第一版软件的产品边界、系统架构、运行状态、数据模型、通信方式、性能策略和硬件适配关系。实施顺序与验收门槛见上级目录中的 `workflow/MII_软件开发与验证工作流_v1.0.md`。

## 2. 产品目标

MII 是一台低功耗、离线优先的墨水屏信息终端，具有两类主要使用方式：

1. 静态展示：显示用户在 Android App 中自由设计的页面，并嵌入温度、湿度、气压、电量和时间等动态信息。
2. 动态使用：由用户手动启动 GNSS，记录运动轨迹，并在连接 Android 手机后同步和绘制地图。

设备在没有手机时仍应完成页面显示、BME280 采集和 GNSS 记录；手机负责复杂编辑、长期保存、地图绘制和高速数据交换。

## 3. 第一版范围

### 3.1 包含

- Android 单平台 App。
- 一台设备对应一个所有者数据空间。
- 自由拖动的 800 × 480 页面编辑器。
- 文字、固定图形、小面积图片和动态传感器槽位。
- 黑白页面、4 灰阶完整页面和黑白局部刷新。
- BME280 温度、湿度、气压的本地采集、展示、历史查看和 CSV 导出。
- GNSS 手动开始、暂停、继续、结束、断点记录、地图展示和 GPX 导出。
- BLE 绑定、控制、状态查询和慢速同步。
- 家庭局域网或手机临时热点上的高速同步。
- 手机本地数据库、模板版本和数据备份。
- 固件本地导入与 OTA 更新。

### 3.2 不包含

- 云端服务器和远程账户。
- 互联网远程推送和远程控制。
- 多用户共享设备。
- 环境阈值提醒。
- 墨水屏动画和设备端地图。
- 设备端通用字体排版、图片缩放或自由编辑。
- 全天后台扫描和永久 BLE/Wi-Fi 连接。

## 4. 总体架构

```text
┌──────────────────────── Android App ────────────────────────┐
│ 模板编辑 │ 页面编译 │ 设备管理 │ 环境历史 │ 轨迹地图 │ 备份 │
│       Room + 私有文件 + BLE客户端 + 本地HTTPS同步服务       │
└───────────────────────────┬──────────────────────────────────┘
                            │ BLE / 局域网Wi-Fi / 临时热点
┌───────────────────────────▼──────────────────────────────────┐
│                         MII V7                               │
│ 状态机 │ EPD │ BME280 │ GNSS │ 本地环形存储 │ BLE/Wi-Fi    │
└──────────────────────────────────────────────────────────────┘
```

Android App 是已同步数据的长期权威来源；MII 是尚未同步的传感器与轨迹数据的权威来源。双方通过唯一 ID、序号和同步游标实现增量同步。

## 5. 技术选型

| 范围 | 技术 | 原因 |
|---|---|---|
| 固件 | ESP-IDF + C++ | 直接适配 ESP32-S3、FreeRTOS、低功耗和硬件驱动 |
| Android | Kotlin + Jetpack Compose | 原生 BLE、Wi-Fi、后台任务和 Canvas 能力 |
| 本地数据 | Room/SQLite + App 私有文件 | 离线可靠、易查询、适合单机数据中心 |
| 设备协议 | Protobuf；固件端 nanopb | 跨 C/C++ 与 Kotlin 生成一致消息 |
| App内部接口 | Repository + Use Case | 隔离 UI、Room、BLE 和局域网传输 |
| 构建组织 | 单仓库、多工程 | 硬件、协议、App 和文档版本保持一致 |

第一版不创建独立服务器工程；未来如增加云端，只在 Android 数据层新增远端数据源，不改变设备驱动和模板模型。

## 6. 设备运行状态

### 6.1 顶层状态

```text
SHUTDOWN              真正关机，墨水屏保留画面，不采样、不联网
BOOTING               上电保持、自检和状态恢复
DISPLAY_INTERACTIVE   按键交互、页面切换和手动刷新
DISPLAY_STANDBY       定时唤醒采集BME280，其他时间深度睡眠
GNSS_ACQUIRING        GNSS上电并搜星
GNSS_TRACKING         运动轨迹记录
GNSS_PAUSED           轨迹暂停，短时保留定位上下文
SYNC_BLE              BLE控制或小数据同步
SYNC_WIFI             局域网/热点批量同步
OTA_UPDATING          固件校验、写入和切换
RECOVERY              模板、存储或升级恢复
```

### 6.2 关键互斥

- `GNSS_TRACKING` 中不启动 Wi-Fi 批量同步或 OTA。
- `SYNC_WIFI` 中不执行 4 灰阶整页合成。
- EPD 刷新只能由显示任务持有。
- Flash 记录写入只能由存储任务持有。
- 正常关机必须等待关键数据提交；硬件长按复位依靠日志格式恢复。

## 7. 按键交互

| 输入 | 默认行为 |
|---|---|
| 电源键长按 | 开机；运行时进入关机确认并执行正常关机 |
| 电源键短按 | 进入、确认或唤醒 |
| 左键短按 | 上一页/上一项 |
| 右键短按 | 下一页/下一项 |
| 电源键+左键 | 刷新当前页面 |
| 电源键+右键 | 开始、暂停或继续 GNSS；结束需要二次确认 |
| 左右键同时长按 | 返回主页或退出非关键交互 |

GPIO0 同时承担 BOOT 功能。启动后必须等待功能键释放，再启用普通按键语义；不能在复位阶段驱动 GPIO0。

## 8. 固件架构

```text
Application State Machines
        ↓
Device Services
        ↓
Hardware Drivers
        ↓
Board Support / ESP-IDF
```

### 8.1 板级支持

`board_v7` 统一定义 GPIO、极性、总线、屏幕方向、无 PSRAM、8 MB Flash 和电源域。业务组件不得包含裸 GPIO 编号。

### 8.2 驱动组件

- `power`：PSHOLD、电源键、充电、PGOOD、电池 ADC、关机时序。
- `buttons`：消抖、长短按、组合键、GPIO0 启动保护。
- `epd`：SSD1677、SPI、BUSY 超时、黑白、4 灰阶、局刷、休眠、流式显示。
- `bme280`：0x76、校准参数、强制测量、总线恢复。
- `gnss`：GPIO15 控电、UART、NMEA、1PPS、定位质量。
- `storage`：设置、模板、环形记录、CRC、断电恢复。
- `ble`：绑定、控制、状态、分块与断点。
- `wifi`：家庭网络、手机热点、本地 HTTPS 客户端和超时。

### 8.3 长期任务

建议只保留：

```text
Application/Event Task
Display Task
GNSS Task
Storage Writer Task
Connectivity/Sync Task
```

BME280 由定时唤醒和事件驱动，不创建永久任务。ISR 只记录最小信息并投递事件，不进行解析、日志格式化或文件操作。

## 9. 显示与模板

### 9.1 编辑态与设备态分离

Android 保存完整的可编辑文档：

```text
TemplateDocument
├── templateId / revision
├── screenProfile
├── canvas
├── elements[]
└── draft/published状态
```

发布时编译为：

```text
TemplatePackage
├── manifest
├── backgroundBitmap
├── dynamicSlots[]
├── assets[]
├── formatVersion
└── packageHash
```

静态文字、图片、边框和复杂排版进入背景位图；动态槽位仅保留坐标、尺寸、格式、数据绑定和后备值。

### 9.2 动态绑定

```text
sensor.temperature
sensor.humidity
sensor.pressure
device.battery
device.time
device.wifi
device.gnss
```

第一版不包含 `remote.*` 云端字段。

### 9.3 无 PSRAM 策略

- 黑白完整帧为 48,000 B，4 灰阶完整帧为 96,000 B。
- 页面从 Flash 按行或按块读取并通过 SPI 流式发送。
- 动态区域使用 8～16 KB 固定缓冲，不依赖整屏 `malloc`。
- 模板和图片传输直接分块写 Flash，不在 RAM 保存完整文件。
- Android 负责缩放、抖动、颜色转换和任意中文栅格化。

## 10. BME280 策略

默认平衡档：

- 5 分钟采样一次。
- 数据保存时间、温度、湿度、气压、电量和质量标志。
- 页面最长约 30 分钟刷新一次；用户可手动刷新。
- 省电档为 15 分钟采样，高频档为 1 分钟采样。
- 真正关机后停止采样。
- 不执行阈值判断和告警。

显示值必须带最后更新时间，避免把旧值误认为实时值。

## 11. GNSS 策略

第一版由用户手动启动，支持步行、骑行和其他类型。

| 类型 | 建议记录条件 |
|---|---|
| 步行 | 5 秒或移动 3 米 |
| 骑行 | 3 秒或移动 5 米 |
| 其他 | 默认 5 秒，可在 App 设置 |

定位解析可保持 1 Hz，但只在时间、距离、方向变化、定位质量变化或状态切换时落盘。无效定位形成轨迹断点，不使用伪坐标连接。

数据结构：

```text
TrackSession
  └── TrackSegment[]
        └── TrackPoint[]
```

因 VBCKP 未供电，完全关机后按冷启动处理。短时暂停可保留 GNSS 电源；结束或长时暂停后关闭。

## 12. 本地存储

### 12.1 设备侧

```text
NVS：设置、绑定、Wi-Fi、同步游标
OTA A/B：双固件分区
模板区：当前版本、上一版本、下载临时区
记录区：BME280、GNSS、故障日志的环形块
```

记录块包含 `magic`、格式版本、序号、长度、载荷、CRC 和最后写入的提交标记。未出现提交标记的块在重启后视为无效。

轨迹点在 RAM 中积累 32～64 个后批量写入；暂停、结束、低电量和关机前强制提交。

### 12.2 Android侧

Room 保存：

```text
devices
templates
template_revisions
sensor_samples
track_sessions
track_segments
track_points
sync_checkpoints
firmware_packages
device_events
```

图片、模板包、预览图、GPX、CSV 和完整备份放在 App 私有文件目录，数据库只保存元数据、路径和校验值。

## 13. 通信与同步

### 13.1 传输层

1. BLE：绑定、认证、状态、配置、目录比较、同步协商和小数据。
2. 同一局域网 Wi-Fi：手机启动本地服务，设备作为客户端连接。
3. 手机临时热点：没有共同局域网时使用。
4. 纯 BLE 分块：Wi-Fi 不可用时的后备方式。

### 13.2 同步顺序

```text
BLE认证
→ 交换版本、目录和同步游标
→ 先取回BME280记录
→ 再取回GNSS轨迹
→ Android事务提交并确认
→ 下发设置
→ 下发模板和资源
→ MII校验、切换并报告
→ 必要时最后执行OTA
→ 保存同步检查点
→ 关闭Wi-Fi和本地服务
```

上传数据在 Android 明确确认前不得删除；模板下载必须先写临时区，校验后原子切换并保留上一版本。

### 13.3 协议字段

通用消息至少包含：

```text
protocolVersion
messageId
deviceId
sequenceNumber
sentAt
payloadType
payload
```

大文件分块至少包含 `transferId`、偏移、总长度、块长度和块校验。重复块必须可安全处理。

## 14. 简单安全边界

- 首次绑定显示验证码并要求设备按键确认。
- App 为每台设备生成独立随机密钥和设备令牌。
- 局域网使用手机本地 HTTPS 服务，并在首次绑定时固定手机证书指纹。
- App 侧密钥使用 Android Keystore 保护；设备侧保存在受保护的 NVS。
- 本地接口仅在用户同步期间开启，结束后关闭。
- 不提供任意远程命令、Shell 或公网监听。
- 恢复出厂设置清除绑定、Wi-Fi和令牌。

这是第一版的简化安全模型，不等同于高对抗场景下的完整安全体系。

## 15. Android架构

```text
Compose UI
    ↓ UDF
ViewModel
    ↓
Use Case（仅复杂流程）
    ↓
Repository
    ↓
Room / BLE / Local HTTPS / Files
```

一级页面：

1. 设备：状态、屏幕预览、最新 BME280、同步、切页和刷新。
2. 设计：模板编辑、模拟数据、编译、发布和版本恢复。
3. 数据：环境历史、CSV、运动列表、地图和 GPX。
4. 设置：采样档位、刷新策略、家庭 Wi-Fi、固件、备份和恢复出厂。

模板编辑器使用 Compose Canvas；拖动阶段只修改元素状态，发布阶段才生成最终位图。轨迹地图按缩放级别抽稀显示，原始数据保留用于导出。

## 16. 性能边界

当前硬件可以实现第一版全部功能，但必须遵守：

- 不同时运行 GNSS 批量写入、Wi-Fi 大传输和 4 灰阶整页渲染。
- 不把完整模板、图片或轨迹加载到 RAM。
- 无线同步和显示刷新使用固定上限的分块缓冲。
- 设备端活动页面数量根据最终分区表限制，初始目标为 4～8 页。
- 固件 OTA A/B 和至少约 3 MB 数据空间必须通过实际编译确定。
- 每个关键场景记录最小空闲堆、最大连续块、任务栈余量、耗时和电流。

编译通过、示例运行或开发板测试都不构成性能结论；最终以 MII V7 实物板测试为准。

## 17. 硬件需求追踪

| 硬件需求 | 软件组件 | 关键处理 | 实物退出门槛 |
|---|---|---|---|
| GPIO21保持电源 | power/board_v7 | 启动尽早拉高，关机最后释放 | 100次开关机无异常掉电 |
| GPIO0兼作BOOT | buttons/board_v7 | 启动等待释放、禁止输出 | 按住/释放/复位场景均正确 |
| BAT_ADC高阻分压 | power/battery | 稳定延迟、多点采样和校准 | 与外部测量误差在确定范围内 |
| EPD无PSRAM | epd/storage | Flash流式发送、小缓冲 | 黑白/4灰/局刷无内存失败 |
| EPD BUSY | epd | 所有等待有超时和恢复 | 拔屏或BUSY异常不死机 |
| BME280 0x76 | bme280 | ID、校准、强制测量 | 连续采样和断线恢复通过 |
| GNSS控电 | gnss/power | GPIO15高开低关 | 冷启动、关闭和重启通过 |
| GNSS无VBCKP | gnss/application | 冷启动UI和超时，不假设热启动 | 实测搜星流程与状态一致 |
| 1PPS | gnss/time | ISR只入队时间戳 | 长时间运行无中断阻塞 |
| BLE/Wi-Fi共用射频 | connectivity | 分阶段工作和资源回收 | BLE切Wi-Fi循环无泄漏 |
| Flash有限且需OTA | storage/build | A/B固件、环形数据和配额 | 实际镜像、分区和满盘测试通过 |

## 18. 失败与恢复

- 驱动初始化失败：隔离对应功能，保留可用的基础显示或诊断页面。
- EPD 刷新失败：保留上一画面，记录错误，下次完整初始化。
- BME280 失败：槽位显示 `--` 和旧数据时间，不伪造读数。
- GNSS 失败：结束或暂停当前分段，保留已记录轨迹。
- 同步失败：保存检查点，下次从已确认偏移继续。
- 模板损坏：回滚上一模板。
- 数据区损坏：按块 CRC 扫描，跳过损坏块并报告。
- OTA失败：由启动回滚机制恢复上一固件。

## 19. 版本规则

独立维护：

```text
hardwareRevision
firmwareVersion
protocolVersion
templateFormatVersion
templateRevision
storageFormatVersion
androidAppVersion
```

协议和存储格式只允许向后兼容增加字段；删除或改变字段语义必须提升主版本并提供迁移方案。

## 20. 设计结论

MII V7 的 CPU、接口、8 MB Flash、墨水屏、BME280、GNSS、BLE 和 Wi-Fi 能覆盖第一版需求。无 PSRAM 是主要工程约束，但通过 Android 预渲染、设备流式显示、固定缓冲、分块传输、环形日志和任务错峰可以适配。

这一结论确认的是架构可实现性。驱动正确性、持续运行、搜星时间、墨水屏残影、存储寿命和功耗必须按工作流在现有 V7 实物板上取得记录后才能称为验证通过。
